# Gitstar 2.0.0 · Windows x64 使用说明

这是第一版可运行的 WPF 应用。已接入真实 GitHub API；尚未使用你的账号完成 OAuth、私有仓库、源码推送和版本发布验收。

## 启动

底部信息栏固定为单行摘要，长消息以省略号显示。点击信息栏或“详情”打开完整消息，可复制详情或进入任务记录，Git 原始错误不会丢失。

源码工作区新增“核对同步”，区分本地领先、远端领先、双方都有新提交和两边历史独立。远端领先时可在干净工作区安全快进；双方各有提交时需先合并。两边没有共同历史时，可确认差异后“修复本地历史”：保留本地文件快照、创建原本地提交备份分支，再以远端提交为父提交建立新的本地提交，不直接推送。完成后点击“更新”正常上传。

“强制更新远端”在执行前展示仓库、分支、双方提交与影响，并要求确认。保留远端旧提交的本地 `gitstar-remote-backup/…` 备份分支，仅更新指定分支，使用明确期望远端 SHA 的 `--force-with-lease`；远端在核对后又有变化会拒绝覆盖。脏工作区或本地提交已变化时不能执行，完成后读取远端确认。此选项需要有效的 GitHub 推送权限，仍受分支保护规则限制。

最近更新卡片的更多按钮进入“关注与分组管理”，同一窗口可设置 GitHub Star、本地关注和所属分组，也可新建分组。两种关注方式可独立保留，同时存在时优先显示 GitHub Star；只调整本地关注不要求登录。GitHub 分组需要先 Star，保存时合并本次调整并保留未改动的分组。

取消 Star 或本地关注后，“取消关注历史”记录仓库、原关注方式、操作时间和原分组，按当前账号分别保存，最多保留最近 500 条。可恢复为 GitHub Star 或本地关注：Star 恢复须登录并核对远程结果，本地恢复不写入 GitHub。只恢复仍存在的原分组，不重建已删除分组；恢复 Star 成功但分组未确认时会保留提示。历史入口位于关注管理、批量管理和设置的“关注列表”。旧版隐藏项目可恢复，但取消时间与原关注方式显示为未知；无法补录此前在 GitHub 网页等外部取消的 Star。

主窗口默认约为 1180 × 760，居中显示；较小屏幕或较高缩放下按比例缩小并保留桌面空间，可手动调整大小或最大化，不再强制占满屏幕高度。

设置中的“开机静默启动”显示启动项的注册表位置、值名称、当前程序路径、已登记命令及应使用的静默命令。“核对启动项”只读取状态；“修复静默启动”立即启用并将当前用户的 Gitstar 启动项改为当前程序的完整路径加 `--tray`，写入后再次核对。可复制启动项位置或打开程序目录；不会改动其他应用的启动项。若在 Windows 任务管理器中禁用了 Gitstar，需要在那里重新启用。

在“本机可更新”点击“软件管理”，统一管理全部已关联软件，可搜索软件或仓库，并按正常检查、停止、暂停和忽略状态筛选。支持逐项勾选、全选当前筛选结果，批量忽略各软件当前版本、暂停 7 天、停止或恢复检查，以及解除关联。切换搜索或筛选会清除之前的选择，避免误操作隐藏项目；解除关联需要确认，保留本机软件、便携软件记录及已下载安装包。没有版本缓存的软件会跳过“忽略当前版本”，并提示先检查更新。

每项可点击“修改匹配”，调整本机软件、GitHub 仓库、主程序 EXE、版本通道、标签前缀和安装包规则。更换匹配时清除旧版本忽略记录，保留暂停和停止状态；关联冲突会提示先处理已有项。更新卡片的更多按钮也进入这一管理窗口。修改和恢复后立即按缓存更新待更新列表，不发起全机扫描；点击“检查更新”获取已关联仓库的最新版本。

“保存安装包”窗口默认选择最新版本，并标明正式版或测试版。版本列表首批读取 30 条发行记录，可点击“加载更多版本”查看更早版本；切换版本后，安装包列表同步切换。默认版本沿用当前版本通道和更新检查的版本选择规则，GitHub Latest 正式版独立读取；加载更多时保留已选版本。只保存所选版本与安装包，不启动安装器；手动保存的历史版本不会被“只保留最新版本”自动清理。下载目录仍平铺，重名与同版本文件按原设置处理。“下载并安装”继续使用本机已匹配的更新目标。

收起到托盘或最小化后，空闲约 10 秒会释放卡片、项目详情、解码头像和数据库页缓存，并回收暂时不用的内存。运行中的任务及打开的对话框会延后回收；扫描仍最多 24 个仓库并行，下载和发布继续执行。重新打开窗口直接用已有数据恢复页面、选中项目和勾选项，不触发重新扫描。仅在进入后台空闲状态或后台任务结束后回收，不定时反复压缩工作集。内存数值会随数据量、任务和窗口恢复变化；驻留内存、进程已提交内存与托管堆是不同指标。

安装 **x64 .NET Desktop Runtime 10.x**，再运行 `Gitstar.exe`。免安装版和安装版均不携带运行时。下载地址：https://dotnet.microsoft.com/download/dotnet/10.0 。请选择 Desktop Runtime，不是 SDK 或仅 .NET Runtime。

- 免安装版：直接运行 `Gitstar.exe`。
- 发行目录：`D:\Agant\Github_Releases\Gitstar\`，所有文件直接放在此目录，没有发行子文件夹：`Gitstar.exe`、`使用说明.md`、`Gitstar-setup.exe`、`SHA256SUMS.txt`。不生成 ZIP。DLL、运行配置及资源已打包到 EXE，Git 认证直接调用 EXE。构建完成后，最新精简源码自动同步到 `D:\Agant\Github_Source\Gitstar`，保留该目录的 Git 信息，排除编译产物、工具链和外部参考仓库。源码保留必要的工程目录结构。普通修改覆盖最新版；构建脚本可通过 `-OutputRoot` 和 `-SourceRoot` 自定义发行目录及源码上级目录。
- 安装版：运行 `Gitstar-setup.exe`，安装到当前用户目录。安装器会检查运行时，不会下载或安装运行时。
- 配置和 SQLite 数据库：`%LOCALAPPDATA%\Gitstar\gitstar.db`。凭据使用当前 Windows 用户的 DPAPI 加密。账户缓存与任务记录按账号隔离。卸载保留个人数据。
- 设置中的“本地数据与清理”显示当前用户实际的数据目录和数据库路径，可打开目录或复制路径。删除运行残留数据时，先从系统托盘选择“彻底退出”，再删除整个应用数据目录（包含数据库及可能存在的 WAL/SHM 文件）；登录、设置、分组、软件/源码关联、缓存和任务记录会一并清除，之后启动恢复初始状态。下载目录中的安装包需单独整理。
- “本地数据与清理”中的“按模块清理缓存”支持单选、多选及全选：最近更新、本机可更新、我的项目、作者头像、已结束任务记录。显示缓存内容大小，清理后整理 SQLite 空闲空间。当前账号的模块缓存单独清理，头像是此 Windows 用户的共享缓存；其他账号缓存保留。
- “本地数据与清理”显示数据库文件大小、有效内容和可回收空闲页。“整理数据库空间”仅回收 SQLite 空闲空间，保留全部记录；无需删除数据库。也可按模块清理不需要的缓存。彻底退出时，空闲空间达到 8 MB 且占数据库三分之一以上会自动整理，避免长期占用已腾出的空间。
- 模块清理保留登录凭据、设置、本地关注与分组、软件绑定、便携软件、源码关联、自动发布配置及安装包下载记录，不删除源码或已下载文件。最近更新与本机更新保留各自需要的版本快照；清理最近更新后，本机可更新结果仍可使用。清理本机结果后可手动检查重新获取，清理我的项目后可刷新项目列表。
- 任务记录仅清理已完成和已取消且没有待核实结果的记录；进行中、暂停、失败以及所有远程结果待核实的记录保留。清理前有确认，任务历史清理后不能恢复。清理操作需等待其他任务结束，避免缓存写入冲突。
- 认证后令牌、Client ID、偏好、账号档案、仓库/版本/分组缓存及任务记录均保存在此数据库；访问令牌、续期令牌及其授权记录使用 DPAPI 加密，缓存与设置不做整体数据库加密。数据库运行期间可能出现 `gitstar.db-wal`、`gitstar.db-shm` 临时文件。更换 EXE 或发行目录继续使用同一份数据，无需迁移；DPAPI 凭据不能直接复制给另一 Windows 用户使用。
- 关闭右上角 X 收起托盘；托盘菜单“彻底退出”关闭程序。自启动默认关闭，可在设置启用。登录 Windows 后静默进入托盘，不显示主窗口或任务栏按钮；双击托盘图标或选择“打开 Gitstar”查看页面。手动重复启动打开现有窗口；重复的开机自启动保持后台运行，不唤起窗口。
- 主窗口默认居中，高度为所在屏幕工作区（扣除任务栏）的 100%（由原 80% 增加 25%），考虑 DPI 缩放。不会默认最大化；你仍可手动调整或最大化。弹窗高度也限制在工作区的 80% 以内。

## 登录与收藏

1. 在 GitHub Settings → Developer settings → OAuth Apps 创建自己的 OAuth App。Device Flow 不使用回调交换 Client Secret；请启用 **Enable Device Flow**。不要把 Client Secret 填入客户端。
2. 点击“登录 GitHub”。未配置 Client ID 时先打开默认浏览器登录 GitHub，应用内引导创建 OAuth App、填写 Client ID 并保存授权。配置完成后获取授权码，自动打开浏览器设备授权页面；授权窗口另有“打开浏览器登录”按钮可重新打开。授权码尽量自动复制，剪贴板不可用时可手动复制。
3. 授权 `repo user workflow`。`repo` 是覆盖私有仓库的宽范围权限；`workflow` 用于提交 GitHub Actions 文件。user 是较宽的用户读写权限，用于 GitHub Star Lists 管理，由浏览器授权页确认；本应用不请求删除仓库权限。
4. 登录后同步 Star、Lists 与 Release。无法读取 Lists 时会显示错误并保留已有分组；可以本地添加或导入分组。本地分组独立保存；明确选择 GitHub 分组时会写回 GitHub。
5. 未登录可通过“添加项目”添加公开仓库。私有仓库必须登录且账号具有权限。

启用 GitHub 的“Expire user access tokens”时，新版将加密保存续期令牌和有效期，在请求前自动续期；正常重启不需要浏览器授权。旧版仅保存访问令牌，无法恢复已经丢弃的续期令牌；如旧授权到期，请在设置重新授权一次。临时网络故障保留凭据，不要求反复登录；续期令牌到期或被撤销时才需重新授权。退出账号会清除访问和续期凭据。

## 两个页面

**最近更新**：顶部“最近 7 天更新”统计当前分组、搜索和版本通道下，近七天发布版本的项目数，同仓库只计一次；列表仍可浏览较早版本。卡片使用仓库作者（owner）的 GitHub 头像，异步加载，头像缓存于 `%LOCALAPPDATA%\Gitstar\avatars`，七天后按需更新，内存头像缓存最多约 64 个已完成条目；无法加载时显示作者首字母。左侧分组栏点击切换全部收藏、未分组、GitHub Lists 与本地/导入分组，显示来源和项目数，同名分组保持独立。默认显示“正式 + 测试”，可结合搜索和正式/测试通道浏览，每仓库展示符合筛选的最新 Release。卡片最多预览三行更新内容，过滤重复日期/版本等无效标题，没有有效内容时收起摘要；“更新日志”仍显示作者完整原文。选择具体 Windows / Android 安装包和目录；只下载，不启动安装器。浏览测试版不会改变本机软件的订阅。

**本机可更新**：点击本页“检查更新”只复检已关联的软件及对应仓库：直接读取已绑定的登记项或便携路径，不枚举所有软件，不同步 Star/分组，不检查其他收藏仓库；尚无关联时提示先匹配。全量发现软件仍通过“自动匹配 / 批量关联”。局部检查保留其他收藏缓存，不重置后台全量刷新周期。

从 Windows 卸载注册表发现程序，再核对主程序文件的产品版本/文件版本，点击“自动匹配 / 批量关联”。优先匹配软件登记的 GitHub 地址，其次在已同步仓库中匹配名称；明确地址和唯一同名候选默认勾选，可一次确认多个软件。多作者同名、名称相近或未识别项不默认勾选，可在列表修改/粘贴仓库并批量确认。匹配不是所有软件都能识别，仍保留“手动管理 / 便携软件”入口处理特殊项目、标签前缀、暂停和忽略选项。已有绑定及其设置不会被批量操作重写。

- 本机版本优先采用可识别主程序的产品版本，其次文件版本；排除卸载器、更新器和辅助服务，不会直接套用 GitHub 最新版本。便携软件每次扫描也复检目录或指定 EXE。多个候选不按最高版本猜测；可在“手动管理 / 便携软件”中选择主程序 EXE。悬停卡片版本号查看来源、路径和原登记版本。主程序无法识别时保留登记/手动版本并说明未验证；明确失效的安装目录标记未知。手动“检查更新”先强制刷新本机版本，再请求 GitHub。
- 只有版本可比较且新版高于当前版时进入更新列表。未知版本保留待确认，不自动升级/降级。
- EXE/ZIP 支持标注 x64 或 x86 的 Windows 安装包；64 位 Windows 可安装两种架构，32 位 Windows 仅可安装 x86。MSI 允许未在文件名标注架构，下载校验后读取内部 Template Summary，确认兼容后才打开安装器。ARM64、Itanium、无效 MSI 不会启动。多个候选包由你选择。
- 按钮在执行时显示下载百分比和进度条、校验中、解压中、等待安装确认及安装器运行中；悬停显示已下载容量或阶段说明。切换页面后保留进行中的按钮状态，失败/暂停后可重试，重试重新下载。
- EXE/MSI 下载并校验后询问是否打开安装器，由你完成安装。安装器运行期间显示不确定进度，不提供虚构百分比；退出后重新读取已安装版本，确认达到目标才算更新成功，未确认时按钮提供“重新检测版本”。安装器把任务交给其他进程时也可能需要稍后重新检测。点击“检查更新”重新扫描实际版本；切换页面不触发扫描或联网。
- ZIP 解压到带时间的新目录并打开文件夹，保留旧版本；迁移配置后请重新关联便携目录和版本。
- 提供 SHA-256 时核对摘要；作者未提供时明确提示仅能核对大小，需你确认继续。
- 默认下载目录为 `Downloads\Gitstar_Download`。安装包直接放在所选目录，不创建项目或版本子文件夹；使用 Release 附件原名，保留中文、空格、大小写和版本号，不添加项目名、版本前缀或哈希。不能用作 Windows 文件名的附件会提示错误，不静默改名。同名文件不自动添加序号；无法确认可替换时提示更换目录或移走原文件。旧命名文件的下载记录仍可识别，本次命名变更不批量重命名已有文件。
- 设置中的“同版本安装包已存在时”可选每次询问、重新下载并替换、跳过下载和安装。默认询问；重新下载时旧文件保留到新文件校验成功。只处理已记录且内容未变的安装包，用户修改的文件保留。历史项目子目录的记录仍可校验与清理；旧下载文件不会自动搬迁。失败/暂停的 `.partial` 不可安装，重试重新下载。
- 更新选项支持忽略当前 tag、暂停至日期、停止检查；在关联窗口清空忽略/暂停或取消停止检查可恢复。

## Star 与分组管理

- 旧版授权只有 read:user，可以添加 Star 但缺少分组写入权限。请在设置点击“重新授权 GitHub”，确认新增 user 权限；配置和缓存保留。已添加项目无需再次添加 Star，在卡片 ··· → 修改分组中勾选目标分组并保存。写入前检查权限，失败显示具体原因，返回归属与提交不一致时不会报成功。
- 左侧“收藏分组”旁的 ＋ 新建 GitHub 或本地分组；右键分组可改名、修改说明或删除。删除分组保留项目 Star 和本机软件关联。
- “添加项目”支持仓库链接或 owner/repo，可选择 GitHub Star 或仅本地关注，并加入多个分组。只读取该项目的版本，不重新刷新全部项目。
- 卡片 ··· 中可“修改分组”“管理 Star”或“停止本地关注”。停止本地关注只隐藏最近更新，保留 GitHub Star 及本机关联；重新添加可恢复。取消 Star 可保留本地关注，本机关联始终保留。
- “批量管理”可进入卡片选择，或从全部缓存项目选择（包括没有 Release、已隐藏及本机关联的项目）。选择框位于卡片左上角，不显示文字；普通浏览时隐藏。批量模式支持全选当前列表、清空选择、退出选择。全选覆盖当前分组、搜索及版本筛选下的全部卡片，包括未滚动到的卡片。
- 勾选后再次点击“批量管理”，可批量加入/移出分组或取消 Star。只更改明确选择的分组，保留网页上的其他分组。GitHub 操作需要登录；本地分组不需要。
- 批量任务逐项记录成功和待处理结果，可在“任务”查看；写入结果不明时核实远程状态。创建分组若结果未知，请先到 GitHub 核实，避免重复创建。

列表支持“按发布时间”和“按更新时间”从新到旧排序：前者使用 Release 的发布时间，后者使用 GitHub 仓库的 `updated_at`，不是版本发布时间或源码推送时间。排序选择自动保存，切换只读取缓存。更新时间模式会在卡片标明时间，悬停可同时查看两种时间；旧缓存缺少仓库更新时间时显示“待同步”并排在末尾，点击“检查更新”获取。每个仓库仍展示符合筛选的最新 Release，“最近 7 天更新”仍按版本发布时间统计。本机可更新继续按版本发布时间排列。

版本选择与列表排序分别处理。正式版优先采用 GitHub 指定的 Latest；仓库没有 Latest 时，按可识别版本号的数值选取最高正式版。正式 + 测试会再比较正式版与最高测试版，同版本正式版优先；指定标签前缀的本机关联只在对应产品线中比较，支持四段版本号。可识别版本优先于非标准标签；没有可识别版本时才以发布时间兜底。因此较晚发布的 `v12.4.13` 维护补丁不会盖过 `v13.2.4`。列表按发布时间或仓库 Updated 排列，只改变项目顺序，不改变选中的版本。

版本获取、精简缓存、本机更新判断和卡片展示使用同一套规则。每次检查核实 Latest，并用 ETag 复用未变化的缓存；Latest 接口暂时失败会提示检查未完成，保留上次结果。旧的按时间精简的分页缓存会在下一次检查时失效重取，无需删除数据库或重新登录。

“只保留最新安装包”同样按版本号判断，不会因旧分支补丁晚发布而删除高版本安装包；同版本的不同附件保留。已配置的标签前缀分别清理，不跨产品线、平台、架构和正式/测试通道删除。混合无法识别的标签与标准版本时，保留不确定文件。

## 安装包设置

“最近更新”顶部的“批量下载”可收集最近 30、14、7、3、1 天发布的全部版本附件，默认 7 天、当前分组及筛选结果，可切换全部关注。EXE、MSI、ZIP 默认勾选，也可多选 7z、APK、tar.gz 等格式或填写其他扩展名。先“读取发行包”，再勾选附件并“下载所选”；清单显示数量和大小，包含该周期内的多个版本，不仅是每个项目的最新版本。读取失败的项目单独提示。文件直接平铺保存，不运行安装器；批量选择的全部版本保留，不参与自动安装包清理。所选不同项目或版本的附件原名相同时会提示调整勾选或分批保存到不同目录，不自动改名或静默漏掉附件。同版本可以统一替换或跳过，默认遵循设置询问。下载最多 4 个并行，每个下载和整批任务均可在“任务”暂停、取消。取消整批会停止后续派发并取消已派发子任务；已完成文件保留。

EXE 文件名未标注 x86/x64 时，仍可下载并检测文件中的实际 PE 架构。64 位 Windows 支持 x86、x64 和兼容的 AnyCPU 程序，32 位 Windows 会阻止 x64 程序；ARM 等不兼容架构与伪装成 EXE 的文件不会启动。MSI 继续读取安装包内部架构，安装器均需用户确认后才打开。未知架构的 ZIP 仍需明确的 Windows/架构信息，不推测可执行内容。

收藏分组栏只增加“本地关注”，不新增单独的 GitHub 关注总分组；GitHub 账号收藏仍显示在原有细分组或“未分组”中。同一仓库在两处重复时，以 GitHub 关注显示，本地栏不重复列出；取消 GitHub Star 后，如果仍保留本地关注，会回到本地栏。设置的“关注列表”提供导入、导出：导出时可分别勾选账号关注和本地关注，合并为本地清单；导入可勾选具体仓库，仅加入本机关注，不自动 Star。使用上次同步的账号收藏，私有仓库名称可能包含在清单里，不导出登录凭据、源码或分组设置。新导入仓库点击“检查更新”获取版本。

设置增加三个开关：只保留最新安装包（默认关闭，按项目/平台/正式与测试通道分别保留，同版本其他文件保留）；确认安装成功后自动删除安装包（默认关闭）；更新检查完成后询问是否清理已安装安装包（默认开启，启用自动删除后不再询问）。

下载的文件会建立下载记录，清理前核对保存位置、大小和 SHA256；正在使用的文件、已改变的文件及便携软件主程序保留。历史下载文件不自动清理。安装器退出或本机页面检查确认主程序已达到安装包版本后，才执行删除/询问；选择保留后该文件不重复询问。不同版本继续使用作者的附件原名；原名不同可以共存，原名相同需要处理重名冲突。开启“只保留最新”后，在新文件校验成功时清理符合条件的旧版本。同版本的同一安装包按设置询问、替换或跳过。

## 多任务与任务管理

不同安装包下载、不同仓库的源码上传和发布可同时运行，也可与 24 路版本检查并行。同一保存文件、本机软件安装目标、Git 目录或同一仓库写入会排队；收藏数据的检查和分组写入按共享缓存资源协调。修改账号或网络设置需等待相关任务结束，以免中途切换凭据。

“任务”窗口逐项显示状态和下载进度，提供独立的“暂停”“取消”，还可暂停全部任务。暂停下载保留 .partial，后续重试从头下载；取消删除未完成临时文件，保留已完成安装包。上传/发布已完成的本地或远程部分不回滚，结果不明须核实；暂停/取消安装等待不会关闭外部安装器。托盘彻底退出可暂停全部任务后等待收尾。

失败、暂停、等待和“结果待核实”的任务都可以取消。取消会保存为已取消状态，并隐藏“重试 / 继续”；保留已完成的源码提交、上传附件和 Release ID，不删除远程版本。以后需要重新发布时，可从项目工作台创建新的同步发布任务。

## 我的项目

项目工作区支持“按发布时间”和“按更新时间”排序，切换只使用缓存并保留当前选中项目。发布时间取项目已发布 Release 的最近发布时间；更新时间取 GitHub 仓库的 `updated_at`。没有已知发布时间的项目排在末尾，草稿创建时间与同版本强制覆盖时间不冒充发布时间。

源码状态分别显示检查时间、最近提交时间与说明、已提交快照文件数、未提交变更文件数、本地累计提交次数，以及 GitHub 核实时间。已提交快照指当前 HEAD 包含的文件；未提交变更可能是这些文件的修改、删除或新文件，两项不是互斥统计。提交后重新读取当前状态；远端核实失败时显示未核实，不沿用旧的已同步结论。

Release 分别显示发布时间、最近更新时间、已上传附件数和核实时间。点击“同步版本”会核对关联发行目录中的当前版本附件，计算缺失或 SHA-256 不同的待上传 / 替换数量；远端缺少摘要的附件列为“待校验”，不当作已经一致。强制覆盖、正常发布和同步发布完成后，记录本次完成时间、实际上传数量和复用数量；同版本强制覆盖不会改动首次发布时间，后续同步保留已确认的本机操作时间。

“我的项目”与“最近更新”“本机可更新”并列，是独立项目工作台。左侧列出当前账号拥有及参与协作的仓库，右侧展示仓库资料、源码工作区、最近版本及项目任务。支持搜索、公开 / 私有 / 已关联本地筛选；列表、本地目录关联及版本记录按账号保存，切换页面不刷新，点击“同步项目”或“同步版本”更新。

源码目录不存在或已移除 Git 信息时，工作区显示失效提示并清除旧分支、提交号及变更结果，保留目录关联供重新选择。版本列表标明上次同步结果；“同步项目”同时刷新当前项目的版本，仓库删除或同名重建时按 GitHub 仓库 ID 清除旧缓存。“同步版本”也会核实仓库身份并替换版本列表。网络暂时失败时保留上次同步结果；仓库不存在或无权访问时清除其旧版本缓存。

- 创建公开或私有仓库，填写说明，可选 README 初始提交。已有本地源码建议创建空仓库，随后初始化并上传。
- 项目设置：修改说明、主页、公开 / 私有可见性、已有默认分支；开关 Issues / Wiki / Discussions / Projects、模板仓库、Merge / Squash / Rebase、PR 自动合并、合并后删除源分支、更新落后分支、网页提交 Sign-off 和私有 Fork。先读取 GitHub 当前值，只提交改变的字段；缺少的选项保持禁用，组织策略和订阅限制由 GitHub 校验。
- 支持归档 / 取消归档。已归档仓库先单独取消归档，再改其他设置。可见性或归档变化须输入完整仓库名称确认；公开后代码与历史公开，私有化不会收回公开 Fork，可见性变化会清除 Star / Watch。协作者 / 团队、分支保护与更多设置提供该仓库的 GitHub 管理入口。Fork / 内部可见性通过 GitHub 管理。

- 每个版本的“管理发布包”在应用内列出所有安装包与附件，并在每个文件下显示上传时间（本地时间，精确到秒）；时间来自该附件自身的 GitHub 创建记录，缺少时显示“尚未获取”，点击“刷新附件”重新读取。支持删除单个附件和删除整个发布版本，均需确认具体目标。删除前重新核实权限、版本与附件状态；发现内容变化时要求刷新重新确认。删除后核实远程结果并更新附件数量或移除已删除版本，清除对应的更新缓存。仅操作 GitHub Release，不删除 Git 标签、源码或本地下载文件；锁定版本不能删除单个附件。以后再次同步发布，会按本地配置重新上传附件。

## 托盘与设置

## 简化项目操作

### 同步并发布最新

- “版本与安装包”的“更新”显示已关联发行目录，默认列出符合附件规则的文件。版本号默认留空，从主应用 EXE 或所选应用文件的版本信息读取，读取失败时可手动填写。GitHub 已有同版本时默认跳过；点击更新后可选择“强制覆盖”或“跳过”，只有确认覆盖才更新附件与日志，保留原版本标签和提交。填写新的版本号会正常创建、上传并发布新版本。留空的更新日志保留已有版本日志。

- 在“版本与安装包”点击“切换 / 关联目录”，可单独设置本项目的本地发行目录，并打开关联目录。此设置与自动发布配置共用，手动发布选择安装包时也默认打开该目录；切换不会搬移文件或修改 GitHub 已发布版本。

- “0 个未提交变更”表示文件已经提交，不代表不能更新。点击“检查变更”或打开“上传更新”会重新读取本地文件并核对 GitHub 分支：已同步时显示“源码已与 GitHub 同步”；有本地提交待上传时可推送已有提交。上传前若发现新文件或状态变化，会更新列表供确认，避免只推送旧提交而漏掉修改。安装包有更新时可直接使用“同步并发布最新”，无需制造空源码提交。

- 版本号支持 `1.0.0.0`，不要求增加 `v` 前缀，也不要求将安装包改为带版本号的文件名。编辑或继续草稿时可修改版本标签；`untagged-...` 临时标签显示为未设置版本号，可根据版本名称或配置的版本来源补齐。自动发布可恢复唯一且版本名称匹配的临时草稿，已发布的标签保持不变。
- GitHub 会规范部分特殊字符附件名。上传前使用兼容名称：本地 `使用说明.md` 在 Release 中上传为 `USAGE.md`，其他不兼容名称转换为稳定的文件名，并在附件标签中保留原名。校验清单在暂存副本中同步修改，原发行文件与本地校验清单不变。手动发布和自动发布共用校验与替换流程，已上传且内容相同的附件直接复用。

- 单项目使用“同步并发布最新”，顶部使用“全部同步并发布最新”。按配置自动提交并推送源码、读取当前版本、同步安装包和更新日志，全程不要求逐项核对或再次确认发布。
- 默认尝试识别已关联的源码目录（或 `D:\Agant\Github_Source\项目名`）与 `D:\Agant\Github_Releases\项目名`。能识别有效 Git 根目录及版本来源时直接使用；无法识别时，单项目按钮打开一次“自动发布配置”。配置按账号和项目保存，可选择是否参与全部发布。
- 版本来源支持 props/csproj、package.json、版本文本和 EXE。保留四段版本号；版本含测试标识时自动作为测试版，也可在高级配置指定类型与标签前缀。发行目录内有版本子目录时取版本号最大的目录；平铺目录按版本来源匹配当前安装包，并排除文件名标明的旧版本。检测到源码、安装包版本不一致时任务停止并记录原因。
- 提交包含已暂存、未暂存、新增、删除和重命名的源码，遵循 `.gitignore`。更新日志可读取指定文件；未指定时从最近源码提交生成，并记录安装包 SHA-256。
- 相同版本自动更新附件与日志，保留已有标签；新版本先建立草稿、完成附件校验，再发布。替换时先上传并校验临时附件，再删除同名旧附件并恢复原文件名。未修改的附件直接复用；中断后重试自动核实并继续已完成的部分。
- 全部发布仅处理有提交权限且已配置参与的项目，最多 4 个项目并行，各项目失败不影响其他项目。任务记录中可独立暂停、取消或“重试 / 继续”；详情展示源码提交、版本与附件结果。应用不会在启动或后台检查时自动提交源码。

- 创建项目时可同时选择源码目录，完成创建后自动准备关联并打开上传窗口。有本地源码时创建空远程仓库；目录冲突使用推荐修正方案。
- “切换 / 关联目录”只需选目录并点击“使用此目录”，自动判断已有仓库或初始化需求。异常窗口默认只保留选择目录、推荐方案和取消，具体修正方式及 Git 详情收进高级操作。
- “上传更新”打开即读取变更和当前分支，默认勾选变更，自动生成可修改的提交说明；取消不需要上传的文件后点击上传。没有新变更时可直接推送已有提交。差异、手动分支和提交身份放在高级操作；已配置身份保持不变，缺失时使用 GitHub 用户名和 noreply 邮箱在当前仓库配置，可在高级操作覆盖。
- “发布版本”常用表单只显示版本号、正式/测试、日志和安装包；自动读取本地 HEAD 或远程默认分支，发布前验证远程提交。点击发布版本后自动创建草稿、上传核验并发布；高级操作可选择仅保存草稿，并查看/指定 commit 与草稿 ID。结果不明仍从任务记录恢复。

## 关于与应用更新

设置左侧“关于”显示作者 HuoXiaolin、当前版本、功能简述和项目地址 https://github.com/HuoXiaolin/Gitstar。点击“检查更新”直接核对该项目最新正式版；公开发布无需登录。发现新版本可查看更新日志并打开对应发布页下载，安装仍由你完成。没有正式版或网络异常会显示未完成原因，不误报为已是最新。后台自身更新也使用同一项目地址。

Gitstar 调用 Git 时仅使用应用内保存的 GitHub 授权，禁止外部凭据助手、终端和登录窗口交互；授权失效时在应用内提示重新登录，不更改系统 Git 配置。应用自身更新单独检查，临时不可用不会计入关注项目检查失败；如你主动关注 Gitstar 仓库，其真实访问错误仍会显示。

启动复检会显示已关联软件数量，完成后状态栏显示“启动复检完成”及可更新数量；未关联软件时只加载上次检查结果。任务完成后不会继续保留“正在处理”提示。

自动关注检查只在应用没有其他任务时开始；发布或上传源码会暂停已经开始的自动检查，完成后由后台周期重新安排。手动检查仍独立运行，项目发布继续支持并行。重新登录后按当前模块同步：我的项目页只同步自己的项目，本机更新页只检查已关联软件。Git 操作允许应用内凭据传递，外部 Git 登录窗口仍被禁止。

## 删除项目

在“我的项目 → 项目设置 → 删除项目”点击删除按钮，输入完整的 owner/repo 后才能执行。此功能删除 GitHub 远程仓库及其源码历史、Issues、Releases 和附件，本地源码与发行文件保留。执行前重新核验仓库身份和管理员权限，执行后核实删除结果，再移除项目管理关联与缓存；关联软件暂停检查，其他项目不受影响。旧授权若缺少 delete_repo 权限，可在删除窗口补充授权；未确认删除或结果不明时不会自动重试。


### 发布时同步更新说明

“更新发布版本”弹窗中的“更新说明”默认读取源码目录根部的 `CHANGELOG.md`。可以选择其他 Markdown / 文本文件，也可以切换为“手动输入”并直接修改说明。文件模式每次上传前重新读取内容，读取失败、文件为空或超过 100 KB 时会停止上传并提示修正。

点击“保存说明配置”或执行更新会按当前项目保存来源；后续自动发布使用同一文件或保存的手动说明。选择新的文件会切换回文件模式。安装包更新成功时同步写入 GitHub Release 的说明；同版本仍需确认强制覆盖，跳过上传时不会修改远端说明。
