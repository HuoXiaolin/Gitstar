# Gitstar 1.0.0.0 · Windows x64 单文件开发预览

这是第一版可运行的 WPF 应用。已接入真实 GitHub API；尚未使用你的账号完成 OAuth、私有仓库、源码推送和版本发布验收。

## 启动

安装 **x64 .NET Desktop Runtime 10.x**，再运行 `Gitstar.exe`。ZIP 和安装版均不携带运行时。下载地址：https://dotnet.microsoft.com/download/dotnet/10.0 。请选择 Desktop Runtime，不是 SDK 或仅 .NET Runtime。

- 免安装版：直接运行 `Gitstar.exe`。
- 发行目录：`D:\Agant\Github_Releases\Gitstar\`，所有文件直接放在此目录，没有发行子文件夹：`Gitstar.exe`、`使用说明.md`、`Gitstar-setup.exe`、`SHA256SUMS.txt`。不生成 ZIP。DLL、运行配置及资源已打包到 EXE，Git 认证直接调用 EXE。构建完成后，最新精简源码自动同步到 `D:\Agant\Github_Source\Gitstar`，保留该目录的 Git 信息，排除编译产物、工具链和外部参考仓库。源码保留必要的工程目录结构。普通修改覆盖最新版；构建脚本可通过 `-OutputRoot` 和 `-SourceRoot` 自定义发行目录及源码上级目录。
- 安装版：运行 `Gitstar-setup.exe`，安装到当前用户目录。安装器会检查运行时，不会下载或安装运行时。
- 配置和 SQLite 数据库：`%LOCALAPPDATA%\Gitstar\gitstar.db`。凭据使用当前 Windows 用户的 DPAPI 加密。账户缓存与任务记录按账号隔离。卸载保留个人数据。
- 设置中的“本地数据与清理”显示当前用户实际的数据目录和数据库路径，可打开目录或复制路径。删除运行残留数据时，先从系统托盘选择“彻底退出”，再删除整个应用数据目录（包含数据库及可能存在的 WAL/SHM 文件）；登录、设置、分组、软件/源码关联、缓存和任务记录会一并清除，之后启动恢复初始状态。下载目录中的安装包需单独整理。
- 认证后令牌、Client ID、偏好、账号档案、仓库/版本/分组缓存及任务记录均保存在此数据库；访问令牌、续期令牌及其授权记录使用 DPAPI 加密，缓存与设置不做整体数据库加密。数据库运行期间可能出现 `gitstar.db-wal`、`gitstar.db-shm` 临时文件。更换 EXE 或发行目录继续使用同一份数据，无需迁移；DPAPI 凭据不能直接复制给另一 Windows 用户使用。
- 关闭右上角 X 收起托盘；托盘菜单“彻底退出”关闭程序。自启动默认关闭，可在设置启用。重复启动打开现有窗口。
- 主窗口默认居中，高度为所在屏幕工作区（扣除任务栏）的 100%（由原 80% 增加 25%），考虑 DPI 缩放。不会默认最大化；你仍可手动调整或最大化。弹窗高度也限制在工作区的 80% 以内。

## 登录与收藏

1. 在 GitHub Settings → Developer settings → OAuth Apps 创建自己的 OAuth App。Device Flow 不使用回调交换 Client Secret；请启用 **Enable Device Flow**。不要把 Client Secret 填入客户端。
2. 点击“登录 GitHub”。未配置 Client ID 时先打开默认浏览器登录 GitHub，应用内引导创建 OAuth App、填写 Client ID 并保存授权。配置完成后获取授权码，自动打开浏览器设备授权页面；授权窗口另有“打开浏览器登录”按钮可重新打开。授权码尽量自动复制，剪贴板不可用时可手动复制。
3. 授权 `repo user workflow`。`repo` 是覆盖私有仓库的宽范围权限；`workflow` 用于提交 GitHub Actions 文件。user 是较宽的用户读写权限，用于 GitHub Star Lists 管理，由浏览器授权页确认；本应用不请求删除仓库权限。
4. 登录后同步 Star、Lists 与 Release。无法读取 Lists 时会显示错误并保留已有分组；可以本地添加或导入分组。本地分组独立保存；明确选择 GitHub 分组时会写回 GitHub。
5. 未登录可通过“添加项目”添加公开仓库。私有仓库必须登录且账号具有权限。

启用 GitHub 的“Expire user access tokens”时，新版将加密保存续期令牌和有效期，在请求前自动续期；正常重启不需要浏览器授权。旧版仅保存访问令牌，无法恢复已经丢弃的续期令牌；如旧授权到期，请在设置重新授权一次。临时网络故障保留凭据，不要求反复登录；续期令牌到期或被撤销时才需重新授权。退出账号会清除访问和续期凭据。

## 两个页面

**最近更新**：顶部“最近 7 天更新”统计当前分组、搜索和版本通道下，近七天发布版本的项目数，同仓库只计一次；列表仍可浏览较早版本。卡片使用仓库作者（owner）的 GitHub 头像，异步加载，头像缓存于 `%LOCALAPPDATA%\Gitstar\avatars`，七天后按需更新，内存头像缓存最多约 64 个已完成条目；无法加载时显示作者首字母。左侧分组栏点击切换全部收藏、未分组、GitHub Lists 与本地/导入分组，显示来源和项目数，同名分组保持独立。默认显示“正式 + 测试”，可结合搜索和正式/测试通道浏览，每仓库展示符合筛选的最新 Release。卡片最多预览三行更新内容，过滤重复日期/版本等无效标题，没有有效内容时收起摘要；“更新日志”仍显示作者完整原文。选择具体 Windows / Android 安装包和目录；只下载，不启动安装器。浏览测试版不会改变本机软件的订阅。

**本机可更新**：点击本页“检查更新”只复检已关联的软件及对应仓库：直接读取已绑定的登记项或便携路径，不枚举所有软件，不同步 Star/分组，不检查其他收藏仓库；尚无关联时提示先匹配。全量发现软件仍通过“自动匹配 / 批量关联”。局部检查保留其他收藏缓存，不重置后台全量刷新周期。

从 Windows 卸载注册表发现程序，再核对主程序文件的产品版本/文件版本，点击“自动匹配 / 批量关联”。优先匹配软件登记的 GitHub 地址，其次在已同步仓库中匹配名称；明确地址和唯一同名候选默认勾选，可一次确认多个软件。多作者同名、名称相近或未识别项不默认勾选，可在列表修改/粘贴仓库并批量确认。匹配不是所有软件都能识别，仍保留“手动管理 / 便携软件”入口处理特殊项目、标签前缀、暂停和忽略选项。已有绑定及其设置不会被批量操作重写。

- 本机版本优先采用可识别主程序的产品版本，其次文件版本；排除卸载器、更新器和辅助服务，不会直接套用 GitHub 最新版本。便携软件每次扫描也复检目录或指定 EXE。多个候选不按最高版本猜测；可在“手动管理 / 便携软件”中选择主程序 EXE。悬停卡片版本号查看来源、路径和原登记版本。主程序无法识别时保留登记/手动版本并说明未验证；明确失效的安装目录标记未知。手动“检查更新”先强制刷新本机版本，再请求 GitHub。
- 只有版本可比较且新版高于当前版时进入更新列表。未知版本保留待确认，不自动升级/降级。
- EXE/ZIP 支持标注 x64 或 x86 的 Windows 安装包；64 位 Windows 可安装两种架构，32 位 Windows 仅可安装 x86。MSI 允许未在文件名标注架构，下载校验后读取内部 Template Summary，确认兼容后才打开安装器。ARM64、Itanium、无效 MSI 不会启动。多个候选包由你选择。
- 按钮在执行时显示下载百分比和进度条、校验中、解压中、等待安装确认及安装器运行中；悬停显示已下载容量或阶段说明。切换页面后保留进行中的按钮状态，失败/暂停后可重试，重试重新下载。
- EXE/MSI 下载并校验后询问是否打开安装器，由你完成安装。安装器运行期间显示不确定进度，不提供虚构百分比；退出后重新读取已安装版本，确认达到目标才算更新成功，未确认时按钮提供“重新检测版本”。安装器把任务交给其他进程时也可能需要稍后重新检测。点击“检查更新”重新扫描实际版本；切换页面不触发扫描或联网。
- ZIP 解压到带时间的新目录并打开文件夹，保留旧版本；迁移配置后请重新关联便携目录和版本。
- 提供 SHA-256 时核对摘要；作者未提供时明确提示仅能核对大小，需你确认继续。
- 默认下载目录为 `Downloads\Gitstar_Download`。安装包直接放在所选目录，不创建项目或版本子文件夹；文件名包含项目、版本及原安装包名称，并保留扩展名，区分不同仓库的同名文件。
- 设置中的“同版本安装包已存在时”可选每次询问、重新下载并替换、跳过下载和安装。默认询问；重新下载时旧文件保留到新文件校验成功。只处理已记录且内容未变的安装包，用户修改的文件保留。历史项目子目录的记录仍可校验与清理；旧下载文件不会自动搬迁。失败/暂停的 `.partial` 不可安装，重试重新下载。
- 更新选项支持忽略当前 tag、暂停至日期、停止检查；在关联窗口清空忽略/暂停或取消停止检查可恢复。

## Star 与分组管理

- 旧版授权只有 read:user，可以添加 Star 但缺少分组写入权限。请在设置点击“重新授权 GitHub”，确认新增 user 权限；配置和缓存保留。已添加项目无需再次添加 Star，在卡片 ··· → 修改分组中勾选目标分组并保存。写入前检查权限，失败显示具体原因，返回归属与提交不一致时不会报成功。
- 左侧“收藏分组”旁的 ＋ 新建 GitHub 或本地分组；右键分组可改名、修改说明或删除。删除分组保留项目 Star 和本机软件关联。
- “添加项目”支持仓库链接或 owner/repo，可选择 GitHub Star 或仅本地关注，并加入多个分组。只读取该项目的版本，不重新刷新全部项目。
- 卡片 ··· 中可“修改分组”“管理 Star”或“停止本地关注”。停止本地关注只隐藏最近更新，保留 GitHub Star 及本机关联；重新添加可恢复。取消 Star 可保留本地关注，本机关联始终保留。
- “批量管理”可进入卡片选择，或从全部缓存项目选择（包括没有 Release、已隐藏及本机关联的项目）。选择框位于卡片左上角，不显示文字；普通浏览时隐藏。批量模式支持全选当前列表、清空选择、退出选择。全选覆盖当前分组、搜索及版本筛选下的全部卡片，包括未滚动到的卡片。
- 勾选后再次点击“批量管理”，可批量加入/移出分组或取消 Star。只更改明确选择的分组，保留网页上的其他分组。GitHub 操作需要登录；本地分组不需要。
- 批量任务逐项记录成功和待处理结果，可在“任务”查看；写入结果不明时核实远程状态。创建分组若结果未知，请先到 GitHub 核实，避免重复创建。

## 安装包设置

设置增加三个开关：只保留最新安装包（默认关闭，按项目/平台/正式与测试通道分别保留，同版本其他文件保留）；确认安装成功后自动删除安装包（默认关闭）；更新检查完成后询问是否清理已安装安装包（默认开启，启用自动删除后不再询问）。

下载的文件会建立下载记录，清理前核对保存位置、大小和 SHA256；正在使用的文件、已改变的文件及便携软件主程序保留。历史下载文件不自动清理。安装器退出或本机页面检查确认主程序已达到安装包版本后，才执行删除/询问；选择保留后该文件不重复询问。不同版本使用包含版本号的平铺文件名，开启“只保留最新”后，在新文件校验成功时清理符合条件的旧版本。同版本的同一安装包按设置询问、替换或跳过。

## 多任务与任务管理

不同安装包下载、不同仓库的源码上传和发布可同时运行，也可与 24 路版本检查并行。同一保存文件、本机软件安装目标、Git 目录或同一仓库写入会排队；收藏数据的检查和分组写入按共享缓存资源协调。修改账号或网络设置需等待相关任务结束，以免中途切换凭据。

“任务”窗口逐项显示状态和下载进度，提供独立的“暂停”“取消”，还可暂停全部任务。暂停下载保留 .partial，后续重试从头下载；取消删除未完成临时文件，保留已完成安装包。上传/发布已完成的本地或远程部分不回滚，结果不明须核实；暂停/取消安装等待不会关闭外部安装器。托盘彻底退出可暂停全部任务后等待收尾。

失败、暂停、等待和“结果待核实”的任务都可以取消。取消会保存为已取消状态，并隐藏“重试 / 继续”；保留已完成的源码提交、上传附件和 Release ID，不删除远程版本。以后需要重新发布时，可从项目工作台创建新的同步发布任务。

## 我的项目

“我的项目”与“最近更新”“本机可更新”并列，是独立项目工作台。左侧列出当前账号拥有及参与协作的仓库，右侧展示仓库资料、源码工作区、最近版本及项目任务。支持搜索、公开 / 私有 / 已关联本地筛选；列表、本地目录关联及版本记录按账号保存，切换页面不刷新，点击“同步项目”或“同步版本”更新。

源码目录不存在或已移除 Git 信息时，工作区显示失效提示并清除旧分支、提交号及变更结果，保留目录关联供重新选择。版本列表标明上次同步结果；“同步项目”同时刷新当前项目的版本，仓库删除或同名重建时按 GitHub 仓库 ID 清除旧缓存。“同步版本”也会核实仓库身份并替换版本列表。网络暂时失败时保留上次同步结果；仓库不存在或无权访问时清除其旧版本缓存。

- 创建公开或私有仓库，填写说明，可选 README 初始提交。已有本地源码建议创建空仓库，随后初始化并上传。
- 项目设置：修改说明、主页、公开 / 私有可见性、已有默认分支；开关 Issues / Wiki / Discussions / Projects、模板仓库、Merge / Squash / Rebase、PR 自动合并、合并后删除源分支、更新落后分支、网页提交 Sign-off 和私有 Fork。先读取 GitHub 当前值，只提交改变的字段；缺少的选项保持禁用，组织策略和订阅限制由 GitHub 校验。
- 支持归档 / 取消归档。已归档仓库先单独取消归档，再改其他设置。可见性或归档变化须输入完整仓库名称确认；公开后代码与历史公开，私有化不会收回公开 Fork，可见性变化会清除 Star / Watch。协作者 / 团队、分支保护与更多设置提供该仓库的 GitHub 管理入口。Fork / 内部可见性通过 GitHub 管理。
- 关联现有 Git 仓库根目录、初始化普通源码目录，或克隆仓库到不存在 / 空的目录。关联前核对 origin；不会自动改写已有远程地址、切换分支或强制推送。解除关联只移除 Gitstar 的关联记录。
- “检查变更”读取本地分支、提交、远程地址和文件状态。上传窗口可勾选变更文件、全选、预览差异，支持重命名与删除；未跟踪文件可在本地查看。支持配置当前仓库的提交者名称与邮箱。需要 Git for Windows。
- “提交并上传”只提交勾选路径；已有暂存内容时拒绝操作。推送失败保留本地提交，可用“推送已有提交”重试。不同仓库上传可并行，同一 Git 目录与仓库写入排队。
- 版本管理显示最近 30 个正式版、测试版和草稿及附件数量，可查看日志、编辑草稿和继续上传 / 发布。发布后直接保存已核实的版本详情，更新界面与本地缓存。网页上发布的草稿可点击“同步版本”或该条目的“核实状态”；同步时会逐个核实列表中的草稿，正式版不再显示草稿操作。编辑或继续发布前也会先核实状态，切换页面不自动刷新。已有发布版本通过 GitHub 页面管理。新版本先验证已推送 commit，再创建草稿、上传安装包，点击“发布版本”后自动核验并发布；也可在高级操作选择仅保存草稿。结果不明可从任务记录的 Release ID 核实恢复，避免重复创建。

## 托盘与设置

- 设置中可选择后台刷新频率：仅手动、每小时、每 6 / 12 小时、每天（默认）、每 3 天、每周。切换页面与分组只使用已有缓存，不重新扫描或联网；点击“检查更新”或托盘“立即检查更新”强制刷新，不受后台周期限制。启动时仅在周期到期后检查，唤醒后合并为一次检查，失败时最多每小时重试。后台不自动下载。检查最多同时处理 24 个仓库，状态栏显示已完成数量、当前并行数和累计用时；缓存每五秒及结束时保存，分页检查历史 Release，但常驻缓存仅保留最近正式版、测试版及已绑定标签前缀对应版本；这些版本的日志和安装包保持完整。版本页按账号缓存 ETag 与精简候选，未变化时仍向服务器验证，304 响应复用缓存；新绑定的标签前缀会使不兼容缓存失效。分组首批成员合并读取，超出部分继续分页；启动先显示窗口与缓存，注册表软件检测在后台执行。读取请求超时或单个仓库失败时保留旧数据，限流时停止派发后续检查，稍后重试。托盘显示已确认的本机更新数量；本机软件更新发托盘系统提醒，Star 更新在应用内显示。当前版本使用 Windows NotifyIcon 气泡提醒，尚未实现带操作按钮的 Windows Toast。
- 忙碌退出可取消，或暂停任务后退出；已启动的外部安装器不关闭。

## 简化项目操作

### 同步并发布最新

- 版本号支持 `1.0.0.0`，不要求增加 `v` 前缀，也不要求将安装包改为带版本号的文件名。编辑或继续草稿时可修改版本标签；`untagged-...` 临时标签显示为未设置版本号，可根据版本名称或配置的版本来源补齐。自动发布可恢复唯一且版本名称匹配的临时草稿，已发布的标签保持不变。
- GitHub 会规范部分特殊字符附件名。上传前使用兼容名称：本地 `使用说明.md` 在 Release 中上传为 `USAGE.md`，其他不兼容名称转换为稳定的文件名，并在附件标签中保留原名。校验清单在暂存副本中同步修改，原发行文件与本地校验清单不变。手动发布和自动发布共用校验与替换流程，已上传且内容相同的附件直接复用。

- 单项目使用“同步并发布最新”，顶部使用“全部同步并发布最新”。按配置自动提交并推送源码、读取当前版本、同步安装包和更新日志，全程不要求逐项核对或再次确认发布。
- 默认尝试识别已关联的源码目录（或 `D:\Agant\Github_Source\项目名`）与 `D:\Agant\Github_Releases\项目名`。能识别有效 Git 根目录及版本来源时直接使用；无法识别时，单项目按钮打开一次“自动发布配置”。配置按账号和项目保存，可选择是否参与全部发布。
- 版本来源支持 props/csproj、package.json、版本文本和 EXE。保留四段版本号；版本含测试标识时自动作为测试版，也可在高级配置指定类型与标签前缀。发行目录内有版本子目录时取版本号最大的目录；平铺目录按版本来源匹配当前安装包，并排除文件名标明的旧版本。检测到源码、安装包版本不一致时任务停止并记录原因。
- 提交包含已暂存、未暂存、新增、删除和重命名的源码，遵循 `.gitignore`。更新日志可读取指定文件；未指定时从最近源码提交生成，并记录安装包 SHA-256。
- 相同版本自动更新附件与日志，保留已有标签；新版本先建立草稿、完成附件校验，再发布。替换时先上传并校验临时附件，再删除同名旧附件并恢复原文件名。未修改的附件直接复用；中断后重试自动核实并继续已完成的部分。
- 全部发布仅处理有提交权限且已配置参与的项目，最多 4 个项目并行，各项目失败不影响其他项目。任务记录中可独立暂停、取消或“重试 / 继续”；详情展示源码提交、版本与附件结果。应用不会在启动或后台检查时自动提交源码。

- 创建项目时可同时选择源码目录，完成创建后自动准备关联并打开上传窗口。有本地源码时创建空远程仓库；目录冲突使用推荐修正方案。
- “切换 / 关联目录”只需选目录并点击“使用此目录”，自动判断已有仓库或初始化需求。异常窗口默认只保留选择目录、推荐方案和取消，具体修正方式及 Git 详情收进高级操作。
- “上传更新”打开即读取变更和当前分支，默认勾选变更，自动生成可修改的提交说明；取消不需要上传的文件后点击上传。没有新变更时可直接推送已有提交。差异、手动分支和提交身份放在高级操作；已配置身份保持不变，缺失时使用 GitHub 用户名和 noreply 邮箱在当前仓库配置，可在高级操作覆盖。
- “发布版本”常用表单只显示版本号、正式/测试、日志和安装包；自动读取本地 HEAD 或远程默认分支，发布前验证远程提交。点击发布版本后自动创建草稿、上传核验并发布；高级操作可选择仅保存草稿，并查看/指定 commit 与草稿 ID。结果不明仍从任务记录恢复。
